**สัดส่วนที่วัดได้จริง** บน repo React ขนาดกลาง: `grep -rn "—"` ดิบได้ 709 บรรทัด กรอง comment

### A5 — `·` เมื่อหางเป็นคนละเรื่องกับหัว ⭐ ท่าที่เจ้าของใช้บ่อยที่สุด

> คลังข้อมูลที่ห้า (แอปสร้างเอกสาร · เจ้าของแก้เอง 20 จาก 21 commit)

em-dash 12 จุดที่ถูกตัด **7 จุดกลายเป็น `·` · 5 จุดกลายเป็นเว้นวรรค** และเลือกได้จากหางว่า
มันต่อประโยคเดิมหรือเป็นคนละเรื่อง:

| หางเป็นอะไร | ใช้ | ตัวอย่าง |
|---|---|---|
| **คนละเรื่องกับหัว** (ข้อกำหนด · หมายเหตุ · คำสั่งที่สอง) | `·` | `ลบไม่ได้ · ปิดการแสดงผลแทนได้` · `สูงเกิน 1 หน้า · ซอยเนื้อหา/ลดรูป` |
| **ต่อประโยคเดิม** | เว้นวรรค (A1) | `ยังไม่มีคะแนน กดเพิ่มได้ที่เมนู` · `เต็มพอดี ระวังอย่าเพิ่มอีก` |

**`·` ในสตริง UI เชื่อมประโยคเต็มได้** ต่างจาก register `formal` ที่ `·` เชื่อมประโยคต้องตัด
(SPEC 7a) — ในคลังข้อมูลนี้ 10 จาก 39 สตริงที่มี `·` เชื่อมสองประโยคเต็ม และเป็นผลจากการแก้เอง
ทั้งหมด · ที่ยังห้ามคือ `·` **นำหน้า**สตริง ซึ่งเป็น bullet ไม่ใช่ตัวคั่น (คลังข้อมูลฆ่าทิ้ง 1 จุด)

### A6 — TH-UI-02 ไปกองอยู่ที่ subtitle และ note ใต้หัวข้อ

> คลังข้อมูลที่เจ็ด (flow ขายของในแอปไทย · เจ้าของเปิดหน้าจอจริงแล้วสั่งแก้ทีละ element ราว 40 จุด)
> · ไม่ใช่กฎใหม่ — เป็น**ตำแหน่ง**ที่ A4 ไปกระจุกอยู่ และเป็นตำแหน่งที่ grep ได้จากชื่อ prop

รอบนี้เจ้าของสั่งตัดข้อความที่ซ้ำออก 9 จุด **5 ใน 9 เป็น subtitle หรือ note ที่วางใต้หัวข้อ**
ที่เหลือเป็นป้ายเหนือช่องกรอก ย่อหน้าใต้ตารางราคา และหมายเหตุความเป็นส่วนตัว — ทุกจุดคือ
**ข้อความชั้นสองที่วางติดกับของหลักซึ่งพูดเรื่องเดียวกันไปแล้ว**

| ข้อความที่ถูกตัด | ซ้ำกับอะไร |
|---|---|
| subtitle `ตั้งต้นจากโปรไฟล์ แก้ได้ถ้าฝากให้คนอื่น` | หัวกล่องบอกว่ากล่องนี้คืออะไร และช่องข้างล่างมีค่าตั้งต้นอยู่แล้ว |
| subtitle `ตรวจให้ดี สลักแล้วแก้ไม่ได้` | ติ๊กยืนยันข้างล่างพูดเรื่องเดียวกัน |
| subtitle `ส่งถึงบ้านหลังพิธี` | หัวกล่อง `ที่อยู่จัดส่งของที่ระลึก` |
| note ใต้ชื่อแพ็กสองใบ (`เพิ่ม 100 บาท ได้วิดเจ็ตยาวทั้งปี` · `รับปีละครั้ง ปิดรับก่อนวันงาน`) | bullet ในการ์ดใบเดียวกัน |
| ป้าย `ปีเกิด พ.ศ.` เหนือช่องเลขปี | หัวกล่อง `ตรวจสอบปีชงจากปีเกิด` |
| ย่อหน้าใต้ตารางราคาที่ไล่ว่าแพ็กไหนได้อะไร | บันไดราคาข้างบนแสดงครบแล้ว |

**เช็กพอยต์: เจอ prop ที่แปลว่าข้อความชั้นสอง ให้ถามก่อนว่าตัดแล้วผู้อ่านเสียอะไรจริงไหม**

```sh
grep -rnE "subtitle|description=|helperText|caption=" <path>
```

⚠️ **บางแถวคำตอบที่ถูกคือแก้ที่จอ ไม่ใช่ที่คำ** `ไม่ใส่เวลาเกิดก็ฝากได้ พิธีใช้วันเกิดเป็นหลัก`
จบด้วยการ**ตัดช่องเวลาเกิดทิ้ง** — คำอธิบายที่มีไว้กันผู้ใช้กังวลกับช่องที่ไม่จำเป็น แปลว่าช่องนั้น
ไม่ควรมีตั้งแต่แรก (`false-positives.md` entry 2026-07-30 เรื่องคำสั่งที่ต้องแก้ที่ logic)

## B. ขีดเปล่าแทนค่าว่าง

> TH-UI-03 · hard · คลังข้อมูล · สตริง UI เท่านั้น

`—` ที่ยืนแทนชื่อที่หายไปหรือลิสต์ว่าง อ่านไม่ออกว่าหมายถึงอะไร

| ก่อน | หลัง |
|---|---|
| `{roleLabel ?? '—'}` | `{roleLabel ?? 'ไม่ระบุ'}` |
| `{comment.authorName ?? '—'}` | `{comment.authorName ?? 'ไม่ระบุ'}` |
| `<span>—</span>` (ลิสต์สมาชิกว่าง) | `<span>ไม่พบสมาชิก</span>` |
| `<div>—</div>` (ไม่มีสถิติ) | `<div>ไม่มีข้อมูล</div>` |
| `แก้ไขล่าสุดโดย {note.updatedByName ?? '—'}` | `{note.updatedByName && (<div>แก้ไขล่าสุดโดย {note.updatedByName}</div>)}` |
| `{p.total > 0 ? hm(p.total) : '—'}` | `{p.total > 0 ? hm(p.total) : ''}` (ในตารางที่ช่องว่างอ่านออกเอง) |

**สี่ทางเลือก เรียงตามลำดับที่ควรลอง:** ไม่แสดงบรรทัดนั้นเลย → เว้นว่าง (ในตาราง) →
คำที่บอกว่าทำไมถึงว่าง (`ไม่พบสมาชิก`) → คำกลาง ๆ (`ไม่ระบุ`)

**`ยัง` ไม่ใช่คำฟุ่มเฟือย มันบอกว่าผู้ใช้ยังทำอะไรได้** คลังข้อมูลที่ห้าแยกสองคำนี้ไว้คนละบรรทัด
ในไฟล์เดียวกัน: รายการที่ล็อกแล้วแก้ชื่อไม่ได้ → `(ไม่มีชื่อ)` · รายการที่ผู้ใช้ยังพิมพ์ชื่อได้ →
`(ยังไม่มีชื่อ)` — TH-UI-06 สั่งตัด `ยัง` ที่ซ้ำ แต่ห้ามตัดตัวที่แบกความหมาย "ยังไม่ถึงเวลา" นี้

### B2 — empty state ระดับ section: การบ้านที่ไม่ต้องสั่ง

> TH-UI-09 · **hard เฉพาะฟีเจอร์รอง · ถามก่อนเมื่อเป็น onboarding CTA** · คลังข้อมูล
> · สตริง UI เท่านั้น · ยกกฎ B จากระดับบรรทัดขึ้นเป็นระดับ section (SKILL.md §5 เปิดช่องให้แล้ว)

section ของฟีเจอร์รองที่ทั้งก้อนมีเนื้อหาแค่ "คุณยังไม่ได้ทำ X ไปทำ X สิ" → **ไม่ต้อง render
ทั้ง section** การบอกให้ผู้ใช้ไปทำการบ้านไม่ใช่ข้อมูล

| ก่อน | หลัง |
|---|---|
| heading `ที่ติดตาม` + badge `0` + การ์ด `ยังไม่ได้ติดตามใคร กดติดตามคนที่ชอบ แล้วโพสต์ของเขาจะขึ้นก่อนในฟีด` | ไม่แสดง section นี้จนกว่าจะมีของ |

ตัวอย่างนี้บอกความว่าง **สองรอบ** (badge `0` แล้วการ์ดอธิบายอีกที) ต่อให้เก็บ section ไว้
ก็ต้องเหลืออันเดียว

ขอบเขต:

- **ตัดทั้ง section** เมื่อเป็นฟีเจอร์รอง/ของประดับหน้า ว่างแล้วหน้าไม่เสียความหมาย
- **เก็บ empty state** (แบบ B เดิม) เมื่อ section คือเนื้อหาหลักของหน้า — ตารางที่คนตั้งใจเปิดมาดู
  ว่างแล้วต้องบอกว่าว่างเพราะอะไร ไม่งั้นดูเหมือนโหลดพัง
- **ถามก่อน** เมื่อ empty state เป็น onboarding CTA ของฟีเจอร์ที่ product ตั้งใจดัน
  อันนั้นเป็น product call ไม่ใช่ copy call ห้ามตัดเงียบ ๆ

## C. `— ทีม —` แบบ select placeholder

> TH-UI-04 · hard · คลังข้อมูล · สตริง UI เท่านั้น

| ก่อน | หลัง |
|---|---|
| `{ value: '', label: '— ทีม —' }` | `{ value: '', label: 'เลือกทีม' }` |
| `{ value: '', label: '— ตำแหน่ง —' }` | `{ value: '', label: 'เลือกตำแหน่ง' }` |
| `<label>ทีม</label>` + `'— เลือก —'` | `<label>ทีม</label>` + `'เลือก…'` |

**มี `<label>` ที่มองเห็นอยู่แล้ว → `เลือก…` เฉย ๆ** ไม่ต้องพูดชื่อช่องซ้ำ (ไม่งั้นชนกับ TH-UI-07)
ไม่มี label → `เลือก<คำนาม>` · คลังข้อมูลที่ห้า: `…` ใช้ 18 ครั้ง **18/18 เป็น placeholder หรือ
option ว่าง** ไม่เคยอยู่ท้ายป้าย ปุ่ม หรือหัวข้อ — ถือเป็นเครื่องหมายของ "ช่องที่ยังว่าง"
ตอนเขียน placeholder ใหม่ห้ามกิน `…` ทิ้ง

### D2 — ใน prose ยาว รูปเดียวกันนี้คือ "เอาประธานขึ้นก่อนนามขยายยาว"

> คลังข้อมูลที่หก · เจ้าของกลับด้านประโยคนี้เองในรอบเกลา

AI ชอบวางนามขยายยาวไว้หน้าแล้วปล่อยกริยาไปจบท้ายประโยค คนอ่านต้องอุ้มนามยาวไว้ก่อนจะรู้ว่า
ประโยคกำลังจะบอกอะไร:

| ก่อน | หลัง |
|---|---|
| `คำทำนายที่ระบุวันเวลาแบบตรวจสอบได้ แทบไม่มีในตำราไหนเลย` | `แทบไม่มีตำราไหนที่ระบุคำทำนายวันเวลาแบบตรวจสอบได้` |

## H. Tells สำหรับ prose ยาว (เนื้อหา / บทความ)

### H1 `ไม่ได้ / ไม่ใช่ X แต่ (คือ) Y`

> TH-PR-01 · soft · คลังข้อมูล · ปิดใน `forecast`

AI ตีกรอบด้วยการปฏิเสธก่อน คนไทยพูดตรงกว่า
`การตั้งหลักให้มั่นก่อนเดินต่อไม่ใช่ความอ่อนแอ แต่คือความรอบคอบ`
→ `การตั้งหลักให้มั่นก่อนเดินต่อคือความรอบคอบ`

host form ที่เจอจริงในเนื้อหาไทยคือ `ไม่ได้ X แต่ Y` ไม่ใช่ `ไม่ใช่ X แต่ Y` (คลังข้อมูลที่สี่
นับที่ระยะห่างไม่เกิน 40 อักขระ: `ไม่ได้…แต่` 60→95 · `ไม่ใช่…แต่` 21→25) และ **บรรณาธิการ
มนุษย์สร้างท่านี้ขึ้นเองด้วย** (`ความไม่รู้คือแต้มต่อ` → `ความไม่รู้ไม่ใช่ข้อเสีย`) จึงเป็น tell
เมื่อเป็น**ท่าเปิดซ้ำ ๆ** ไม่ใช่ตอนที่ contrast คือประเด็นจริง — และ **ปิดกฎนี้ใน register
`forecast`** ที่คนเกลาเป็นฝ่ายเติมท่านี้เข้ามาเอง

**variant ที่ตัดได้จริง** `ไม่ใช่แค่ X แต่ยังเป็น Y` — คลังข้อมูลที่สี่ 14→0 อยู่รอด 0% และ
คลังข้อมูลเอกสารทางการ 5→0 เป็น variant เดียวในกลุ่มที่ถูกกวาดทั้งสองคลังข้อมูล
variant ที่ยังไม่พบเลย: `ไม่เพียงแต่…แต่ยัง…` · `ปัญหาไม่ได้อยู่ที่ X แต่อยู่ที่ Y` ·
`คำตอบไม่ใช่ X แต่คือ Y` · negative listing (`ไม่ใช่ X… ไม่ใช่ Y… แต่คือ Z` → พูด Z เลย)
— คง `borrowed` (stop-slop-thai)

### H2 `ยิ่ง X ยิ่ง Y`

> TH-PR-02 · soft · คลังข้อมูล · เป็นสำนวนไทยแท้ ตัดเฉพาะตอนเป็นท่าปิดซ้ำ

`จังหวะนี้ยิ่งไปด้วยกันยิ่งไปได้ไกล` → `จังหวะนี้ไปด้วยกันจะไปได้ไกลกว่า`

เป็นสำนวนไทยแท้ ไม่ใช่ของนำเข้า — ในคลังข้อมูลที่สี่คนเกลา*เพิ่ม*ท่าสั้น (`ยิ่ง` สองตัวห่างกัน
ไม่เกิน 25 อักขระ) เข้ามา 10 จุด อยู่ในอี้จิงทั้งหมด (0→10) เป็น tell เฉพาะตอนใช้เป็น
ท่าปิดซ้ำทุกย่อหน้า

### H3 Closer สำเร็จรูป

> TH-PR-03 · **hard เฉพาะ `นั่นคือ`/`และนั่นคือ` · soft สำหรับที่เหลือ** · คลังข้อมูล
> · ปิดใน `spoken`/`forecast` ที่ย่อหน้าปิดเป็นโครง

`นั่นคือ…` · `และนั่นคือ…` เป็นตัวปิดสำเร็จรูป **hard** — คลังข้อมูล: `นั่นคือ` 14→1 อยู่รอด 7% ·
`และนั่นคือ` 2→0 โปรไฟล์เดียวกับตัวเร่งความแน่นอนใน H5
วิธีแก้: เปลี่ยนเป็นรูปธรรม หรือ**จบก่อนถึง closer** ถ้าประโยคก่อนหน้าอิ่มแล้ว

`ที่แท้จริง` เดี่ยว ๆ **ไม่ใช่ tell** คนเกลาเพิ่มเข้ามาเอง (21→48 อยู่รอด 43%) เป็น **soft**
เฉพาะตอนอยู่ในโครง `นั่นคือ…ที่แท้จริง` ซึ่งทั้งคลังข้อมูลเจอครั้งเดียว (1→0)
ส่วน `อย่างงดงาม` / `อย่างแท้จริง` ย้ายไป H5 แล้ว — เป็น adverb ที่คนไทยใช้จริง

**closer สำเร็จรูปอื่นที่ยืมมา** `โดยสรุป` `กล่าวโดยสรุป` `จะเห็นได้ว่า` `ดังที่กล่าวมาข้างต้น`
`ท้ายที่สุดแล้ว` `หวังว่าจะเป็นประโยชน์` `อนาคตสดใสรออยู่` `ขอให้โชคดี` — ทั้งหมดปรากฏ **0 ครั้ง**
ในคลังข้อมูลไทยทั้งสองชุด คง `borrowed` ไว้ (stop-slop-thai, thai-humanizer) ห้ามอัปเป็น hard

### H4 Tricolon ทุกครั้ง

> TH-PR-04 · soft · คลังข้อมูล · ปิดใน `spoken`/`forecast`

"ตั้งรับ สนับสนุน และอดทน" มีบ้างได้ แต่อย่าให้ทุกบล็อกเป็นสูตรเดียว
สลับเป็นสอง/หนึ่ง/สี่ให้จังหวะต่างกัน — ปิดกฎนี้ใน register `spoken` กับ `forecast`
ที่สามชิ้นเป็นจังหวะที่ตั้งใจ

| ก่อน | หลัง |
|---|---|
| `ตรวจแล้วว่าสะกดถูก เข้าใจว่าสลักแล้วแก้ไม่ได้ และของสั่งทำเฉพาะบุคคลคืนหรือเปลี่ยนไม่ได้` | `ยืนยันตัวสะกดถูกต้อง สินค้าสั่งทำพิเศษไม่รับเปลี่ยนหรือคืน` |

คลังข้อมูลที่เจ็ด · ติ๊กยืนยันก่อนจ่ายเงิน ท่อนกลางถูกกลืนเข้าไปในสองท่อนที่เหลือ (`ยืนยันตัวสะกด`
บอกว่าต้องตรวจตอนนี้ · `ไม่รับเปลี่ยนหรือคืน` บอกว่าทีหลังทำอะไรไม่ได้) — **ย่อ tricolon ที่เป็น
ข้อความผูกพัน ต้องนับเงื่อนไขก่อนและหลัง ไม่ใช่ดูแค่ว่าอ่านลื่นขึ้น**

### H5 ตัวเร่งระดับ `อย่าง + คุณศัพท์`

> TH-PR-05 · **hard เฉพาะตัวเร่ง · soft สำหรับที่เหลือ** · คลังข้อมูล
> แก้ขอบเขต 2026-07-28 · คลังข้อมูลชุดที่สี่ (เนื้อหาไทย 1,670 คู่) — ของเดิมเหมารวมทั้งกลุ่ม
> แล้วยกตัวอย่างผิดสี่คำ

ตัดเฉพาะ **ตัวเร่งระดับ/ความแน่นอน** ที่ไม่เพิ่มข้อมูล:
`อย่างยิ่ง` (97→11) · `เป็นอย่างยิ่ง` (5→0) · `อย่างแน่นอน` (30→1) · `อย่างยิ่งยวด` (3→0)

| ก่อน | หลัง |
|---|---|
| `การเงินอยู่ในเกณฑ์ดีเยี่ยมอย่างยิ่ง` | `การเงินอยู่ในเกณฑ์ดีเยี่ยม` |
| `จะได้รับข่าวดีอย่างแน่นอน` | `จะได้รับข่าวดี` |
| `ช่วงเวลาที่โดดเด่นอย่างยิ่ง` | `ช่วงเวลาที่โดดเด่น` |

**H5 ตัดอย่างเดียว ไม่แตะ `จะ`** การลดความแน่นอนของคำทำนาย (`จะสำเร็จ` → `มีเกณฑ์สำเร็จ`)
เป็นคนละกฎ อยู่ที่ H8 และใช้เฉพาะ register `forecast`

**ห้ามตัด adverb ที่บอกลักษณะ** เพราะมันแบกข้อมูลของมันเอง:
`อย่างต่อเนื่อง` · `อย่างมั่นคง` · `อย่างราบรื่น` · `อย่างเต็มที่` · `อย่างชัดเจน`

`อย่างงดงาม` `อย่างแท้จริง` `อย่างลึกซึ้ง` `อย่างสง่างาม` `อย่างที่สุด` เป็น **soft**: เป็น tell
เมื่อซ้ำในย่อหน้าเดียว ไม่ใช่เจอที่ไหนตัดที่นั่น

| คำ | คลังข้อมูล | อยู่รอด | อ่านว่า |
|---|---|---|---|
| `อย่างงดงาม` | 22→20 | 82% | คนเกลาเก็บไว้ |
| `อย่างที่สุด` | 5→4 | 80% | คนเกลาเก็บไว้ |
| `อย่างลึกซึ้ง` | 11→46 | 73% | คนเกลาเพิ่มเอง |
| `อย่างแท้จริง` | 16→34 | 50% | ก้ำกึ่ง |
| `อย่างสง่างาม` | 8→6 | 38% | ก้ำกึ่ง (×0.51/วรรค) |

สองคำล่างไม่ใช่ของที่คลังข้อมูลคุ้มครอง แต่ก็ไม่ถึงเกณฑ์ hard — ยังคง soft
ส่วนตัวเร่งความแน่นอนข้างบนอยู่รอดกันแค่ 0–5% เส้นแบ่งจึงคมมาก

**ตัวเร่งที่ยืมมาแต่ยังไม่พบ** `อย่างมีนัยสำคัญ` · `ครบครัน` (0 ครั้งทั้งสองคลังข้อมูล) คง `borrowed`
· `อย่างลงตัว` 8→6 อยู่รอด 25% ใช้ได้ · **`อย่างมาก` (73%) กับ `อย่างมีประสิทธิภาพ` (100%)
เป็น native** อยู่ใน `false-positives.md` ข้อ 6

### H6 โครงประโยคซ้ำข้ามบล็อก

> TH-PR-06 · soft · คลังข้อมูล

ถ้าเปิดประโยคด้วยท่าเดียวกันเกือบทุกอัน ("A ซ้อน B —") = ท่าเดียว
สลับการเปิด (ด้วยภาพ / ด้วยสถานการณ์ / ด้วยคำถามในใจ)

### H7 คำเชื่อมฟุ่มเฟือย + nominalization

> TH-PR-07 · soft · คลังข้อมูล (ชุดแรก) · **คลังข้อมูลที่สี่ไม่ยืนยันใน `forecast`** ที่ `ซึ่ง` นิ่ง
> (×1.09/วรรค) ส่วน `สิ่งที่` และ `อย่างไรก็ตาม` เพิ่มขึ้น — ดูตาราง false-positive ในงาน 8f

`ซึ่ง / อันเป็น / โดยที่ / อย่างไรก็ตาม` เกินจำเป็น, `สิ่งที่… / การที่…`

**budget แบบ kien-thai** (borrowed): `ซึ่ง` ≤1/ประโยค — ถ้า antecedent เป็นรูปธรรมใช้ `ที่` ·
`โดย` ≤1/ย่อหน้า · `ในขณะที่` ใช้กับเวลาเท่านั้น ไม่ใช่ contrast (contrast ใช้ `แต่`/`ส่วน`/`กลับ`)

คลังข้อมูลที่สี่ไม่ยืนยัน budget นี้: `ซึ่ง` 246→339 (×1.09/วรรค อยู่รอด 80%) · `โดย` 484→573
(×0.94/วรรค อยู่รอด 83%) · `ในขณะที่` 4→4 — ทั้งสามนิ่ง ไม่ได้ถูกกวาด
ใช้ budget เป็นเป้าตอนเขียนใหม่ได้ แต่ **อย่าไล่ตัดในงานเกลา** ถ้าไม่ได้อ่านแล้วสะดุดจริง

### H8 Hedging เกินเหตุ

> TH-PR-08 · soft · คลังข้อมูล · **กลับทิศใน `formal` และ `forecast`**

`อาจจะ / ค่อนข้าง / ในบางที` ทำให้คำแนะนำอ่อน — house voice = ตรงไปตรงมา
(แต่ไม่ฟันธงหายนะ)

**hedge stack** `อาจจะมีความเป็นไปได้ที่จะ` → เหลือ `อาจ` ตัวเดียวเมื่อไม่แน่จริง (borrowed:
kien-thai · ไม่พบในคลังข้อมูลไทยทั้งสองชุด) · ในกลุ่มนี้ `ค่อนข้าง` อยู่รอด 85% อยู่ใน
`false-positives.md` ข้อ 17

⚠️ **กฎนี้กลับทิศใน register `formal` กับ `forecast`** ที่ต้อง*เพิ่ม* hedge เพื่อลดคำเคลม
เนื้อหาที่ทำนายเรื่องอนาคตให้ผู้อ่านห้ามฟันธง: `จะสำเร็จ` → `มีเกณฑ์สำเร็จ` · `ต้อง` → `ควร`
(คลังข้อมูลที่สี่ นับต่อวรรค: `อาจ` เดี่ยว ×2.11 · `จะ` ×0.74) ส่วน `อาจจะ` ยังตัดเหลือ `อาจ`
ได้ทุก register — เป็น token เดียวในกลุ่มที่คลังข้อมูลเห็นด้วยกับ H8 (`อาจจะ` 34→27 ×0.63
สวนทางกับ `อาจ` เดี่ยว 490→1,304)

**ครอบถึงคำโฆษณาของสินค้าสายความเชื่อด้วย ไม่ได้จบที่ตัวคำทำนาย** (คลังข้อมูลที่เจ็ด)
`คุ้มครองตลอดปี` → `เป็นกำลังใจตลอดปี` — คำที่รับประกันผลเชิงป้องกันเป็นคำเคลม ไม่ใช่คำบรรยาย
สินค้า · จุดนี้ klao เป็นฝ่ายติงเอง (ชนกับข้อห้ามคำรับประกันผลที่ทีมเขียนไว้ในจอรีวิวของตัวเอง)
แล้วเจ้าของเห็นด้วย เป็นเคสของกองขวาใน `SKILL.md` §1 ที่เสนอแล้วได้ผล

## P. อิโมจิในสตริง UI คือไอคอนที่ยังไม่ได้ทำ

> TH-UI-10 · hard · คลังข้อมูล (ชุดที่ห้า) · สตริง UI เท่านั้น

อักขระที่ผู้อ่าน **ต้องถอดรหัส** ไม่ควรอยู่ในสตริง — มันคือไอคอนที่ยังไม่ได้วาด
ส่วนอักขระ **เชิงพิมพ์** ที่อ่านได้ตรงตัวเหมือนเครื่องหมายวรรคตอน เก็บไว้

| ออก (ต้องถอดรหัส) | เก็บ (อ่านตรงตัว) |
|---|---|
| `🔒` `⚠` `📝` `🖨` `↑` `↓` `→` | `·` `…` `＋` `−` `×` `›` `≈` `–` (ช่วง) `“ ”` |

คลังข้อมูลที่ห้า: pictogram กับลูกศร **12 → 0** ในรอบเดียว ส่วนอักขระเชิงพิมพ์รอดครบและเพิ่มขึ้น
(`·` 41→56 · `…` 15→18) — เจ้าของเปลี่ยนอิโมจินำหน้าเป็น `<svg>` จริงทุกจุด

**klao เสนอ ไม่ลงมือ** การถอดอิโมจิออกเฉย ๆ ทำให้ปุ่มไม่มีไอคอน ซึ่งแย่กว่าเดิม
ให้ทำเครื่องหมายไว้ว่า "จุดนี้ควรเป็นไอคอนจริง" แล้วให้เจ้าของตัดสิน — เข้าข่ายห้ามแตะ markup

## I. Opener สำเร็จรูป

> TH-PR-09 · soft · **borrowed** (stop-slop-thai, thai-humanizer) · ยังไม่มีคลังข้อมูลยืนยัน

เปิดเรื่องด้วยของจริง (อาการ ตัวเลข คำถามที่คนถามจริง) ไม่ใช่ท่าเปิดสำเร็จรูป:

- **ยุคสมัย** `ในยุคที่…` `ในยุคดิจิทัล` `ในโลกปัจจุบัน` `ในบริบทของ…`
- **ประกาศสัจธรรม** `เป็นที่ทราบกันดีว่า` `ปฏิเสธไม่ได้ว่า` `แน่นอนว่า` `เป็นที่น่าสังเกตว่า`
- **clickbait** `คุณเคยสงสัยไหมว่า…` `เคยไหมที่…` `ลองจินตนาการว่า…` `จะเป็นอย่างไรถ้า…`
- **ขอเกริ่นก่อน** `ก่อนอื่นเรามาทำความเข้าใจกันก่อนว่า…` `เรามาดูกันว่า…` `มาเริ่มกันที่…`
- **meta** `ในบทความนี้…` `ในส่วนนี้เราจะ…` `ดังที่จะกล่าวต่อไป…`
- **ประโยค generality ว่างเปล่า** (`โลกกำลังเปลี่ยนแปลงอย่างรวดเร็ว`) — ตัดทั้งประโยค ไม่ใช่รีไรต์

⚠️ **หมวดนี้ยังไม่ผ่านการทดสอบ** 17 จาก 18 วลีข้างบนปรากฏ **0 ครั้ง** ทั้งสองฝั่งของคลังข้อมูลไทย
1.8M อักขระ (มีแต่ `ในยุคที่` 2→0) จึงเป็น `soft` และคง `borrowed` ไว้ — ห้ามอัปเป็น `hard`
ด้วยเหตุผลว่า "มีคลังข้อมูลสี่ชุดแล้ว" เพราะไม่มีชุดไหนแตะคำเหล่านี้เลย

## J. กาวย่อหน้าไทย

> TH-PR-10 · soft · borrowed (stop-slop-thai, kien-thai) · **คลังข้อมูลที่สี่เถียง** — ดู
> `references/false-positives.md`

คู่ขนานกับ `Additionally,` ฝั่งอังกฤษ (EN-03): ขึ้นประโยคด้วย `นอกจากนี้` `อีกทั้ง`
`ยิ่งไปกว่านั้น` `ทั้งนี้` `อย่างไรก็ตาม` `ในขณะเดียวกัน` `กล่าวคือ` `โดยเฉพาะอย่างยิ่ง`

ตามจังหวะวรรคละ ~30 อักขระ ส่วน `ยิ่งไปกว่านั้น` `กล่าวคือ` `โดยเฉพาะอย่างยิ่ง` ไม่ปรากฏเลย

**`ทำการ` ต้องดูคำที่ตามมา** ใน 9 จุดของคลังข้อมูล มี 8 จุดเป็นคำประสมไทยแท้ (`ทำการใหญ่` 5 ·
`ทำการค้า` · `ทำการบ้าน` · `ทำการสำคัญ`) ไม่ใช่ translationese และ `ทำการใหญ่` อยู่รอด 2 จุด
ตัวจริงมีจุดเดียว (`ทำการเปลี่ยนแปลง`) → grep ต้องเป็น `ทำการ(?!ใหญ่|ค้า|บ้าน|สำคัญ)`

**แถว passive ไม่ใช่เรื่องสำนวนแปล แต่เป็น register-lift** `ถูก`+กริยา 423→342 และ `โดน` 10→0
(ออก) ส่วน `ได้รับการ` 108→188 · `ผ่านการ` 28→72 (เข้า) — แกนเดียวกับ `คนอื่น`→`ผู้อื่น`
ทิศคือ ปาก/เชิงลบ → ทางการ ไม่ใช่ passive → active

**ใน `formal` กฎนี้กลับทิศ** คนเขียนเติม `ทำการ` `มีการ` `ดังนี้` `ดังกล่าว` เองเป็น convention

## Q. เปลี่ยนโครงประโยค ไม่ใช่เปลี่ยนคำเรียก

> TH-PR-15 · soft · คลังข้อมูลที่หก · ยังไม่มีตัวเลข keep rate จึงเป็น `soft`

อาการ: **แก้คำแล้วยังต้องเติมประโยคอธิบายต่อท้าย** นั่นแปลว่าโครงผิด ไม่ใช่คำผิด
เกิดบ่อยที่สุดเมื่อ**สมาชิกหนึ่งตัวต้องปรากฏสองบทบาทในย่อหน้าเดียว**

ของจริงจากคลังข้อมูล — ประโยคที่บอกว่าโหราศาสตร์หลายชาติสืบจากบาบิโลน แล้วต้องบอกด้วยว่า
บาบิโลนเป็นหนึ่งในสามสายที่คิดขึ้นเอง AI แก้ด้วยการเปลี่ยนคำเรียกสามรอบ ไม่สำเร็จทั้งสามรอบ:

| รอบ | วิธีแก้ | ผล |
|---|---|---|
| 1 | `…รากอยู่บาบิโลน · สามสายคือ **ตะวันออกกลาง** จีน มายา` | อาหรับก็อยู่ตะวันออกกลาง แต่เป็นกิ่ง ขัดกันเอง |
| 2 | เปลี่ยนคำเรียกเป็น `**บาบิโลน**` ตรง ๆ | บาบิโลนโผล่สองครั้งในสองบรรทัดติด ยังงง |
| 3 | เติมประโยคปิดวง `ที่เหลือเป็นสาขาของบาบิโลนทั้งนั้น` | ยาวขึ้น ยังต้องให้ผู้อ่านประกอบเอง |

เจ้าของแก้รอบเดียวจบด้วยการ **เลิกนับเป็นสาม**:

> `โหราศาสตร์ฝรั่ง อาหรับ อินเดีย … ล้วนมาจากบาบิโลน ส่วนอีกสองสายที่คิดเอง คือ จีน และมายา`

จาก "สาม" เป็น "หนึ่งบวกสอง" — สมาชิกที่ซ้ำบทบาทหายไปจากลิสต์ ความกำกวมหายตามไปเอง

**ผลข้างเคียงที่ต้องตามเก็บ:** เปลี่ยนโครงแล้วตัวเลขที่อ้างถึงลิสต์เดิมจะกลายเป็นเลขลอย
(ย่อหน้าถัดไปยังเขียน `และ 3 สายเป็นการนับแบบหยาบ` ทั้งที่ไม่มีลิสต์สามอันแล้ว) — grep คำบอก
จำนวนทุกตัวในย่อหน้าถัด ๆ ไปหลังเปลี่ยนโครงเสมอ

## R. ท่าบอกจุดยืน — ผู้เขียนออกมายืนหน้าเนื้อหา

> TH-PR-16 · soft · คลังข้อมูลที่หก · **ปิดใน `spoken`** ที่การชี้ประเด็นเป็นการพูดคุยตามปกติ

คนละกลุ่มกับ opener สำเร็จรูปในหมวด I เพราะไม่ใช่วลีตายตัว แต่เป็น**ผู้เขียนบอกผู้อ่านว่าควรรู้สึก
อย่างไรกับเนื้อหาที่ยังไม่ได้อ่าน** เจ้าของตัดทิ้งทั้งสองตัวในรอบเดียว:

| ก่อน | หลัง | ตัดอะไร |
|---|---|---|
| `ส่วนที่คนมักเข้าใจผิดคือคิดว่าการที่ทั่วโลกตรงกันแปลว่ายืนยันกันเอง จริง ๆ …` | `ส่วนที่เห็นว่าหลายตำราคล้ายกันทั่วโลกนั้น จริง ๆ …` | ท่าบอกว่าผู้อ่านเข้าใจผิด = สั่งสอน |

| `จุดสำคัญคือ ทุกวันนี้ไม่ต้องเปิดดู…` | `ทุกวันนี้ไม่ต้องเปิดดู…` | เดียวกัน |

ตัวอื่นในกลุ่ม: `ที่น่าสนใจคือ` · `ที่ต้องเข้าใจก่อนคือ` · `หลายคนคิดว่า…แต่จริง ๆ` ·
`ตรงนี้คือหัวใจของเรื่อง` — **ตัดวลีทิ้งแล้วประโยคที่เหลือยืนได้เอง** ถ้ายืนไม่ได้ แปลว่าประโยคนั้น

⚠️ **ไม่ใช่ tell เมื่อวลีนั้นแบกข้อมูล** `ส่วนที่ยังเถียงกันอยู่คือ…` บอกสถานะทางวิชาการจริง เก็บไว้ ·
`ข้อนี้สำคัญที่สุด` ไม่บอกอะไรเลย ตัด — เส้นแบ่งเหมือน TH-UI-08 คือหลังวลีมีข้อมูลไหม

## S. คำซ้ำที่เป็นโครง — คู่ตรงข้ามของ E

> TH-PR-17 · soft · คลังข้อมูลที่หก · **ขัดกับ TH-UI-06 โดยตั้งใจ อ่านเส้นแบ่งข้างล่างก่อนใช้**

เกือบทุกกฎในไฟล์นี้สั่งตัด กฎนี้สั่ง**ห้ามแตะ** สัญชาตญาณของ AI คือหาคำพ้องความมาสลับเพื่อไม่ให้

### S1 — คำซ้ำที่มัดข้ออ้างเข้ากับเหตุผล

| ก่อน | หลัง |
|---|---|

`ขอบ` สามตัวในประโยคเดียวอ่านเหมือนความบกพร่อง แต่เป็นโซ่ที่มัดข้ออ้าง (ต้องมีขอบ) เข้ากับเหตุผล
(ชีวิตไม่มีขอบ · ตารางมีขอบ) เปลี่ยนตัวแรกเป็นคำพ้องความแล้วโซ่ขาด และเหลือสองคำที่หมายถึง
เรื่องเดียวกันอยู่ในประโยคเดียว

### S2 — ศัพท์ที่สรุปต้นเรื่องประกาศไว้ ต้องใช้คำเดิมในหัวข้อและในเนื้อ

| หัวข้อข้อ 1 บรรทัด 41 แก้มาเป็น | `ชุดสัญลักษณ์ที่มีจำกัด` ← คำพ้องความ |
| ที่ลงจริง | `ชุดสัญลักษณ์มีจำนวนจำกัด` |

ห่างกัน 38 บรรทัด ผู้อ่านต้องมาจับคู่เองว่าสองคำนี้คืออันเดียวกันหรือคนละอัน หัวข้อมีหน้าที่

### S3 — ช่องกรอกเดียวกันในหลายตัวเลือก ต้องใช้ป้ายเดียวกัน

### TH-OR-05 — คำสะกดผิด เป็น hard ได้เลย ไม่ต้องรอ keep rate

หมวดนี้ต่างจากทุกกฎในไฟล์ เพราะ**สะกดผิดคือผิด** ไม่มี register ไหนที่ถูก และไม่มีคำไหนที่ต้อง
ชั่งใจว่าเจ้าของตั้งใจหรือเปล่า (ต่างจาก TH-OR-01 ที่ต้องหักอักษรย่อออกก่อน) `กฏ` มาจากงานจริง
ในคลังข้อมูลที่หก ที่เหลือเป็นชุดที่พบบ่อยพอจะคุ้มค่าใส่ในด่านเดียวกัน — **แต่ตัว pattern เองมี FP
หนึ่งตัวที่ต้องกันด้วย lookbehind** ดูใต้โค้ด:

```sh
rg -nP "(?<!ปรา)กฏ|อนุญาติ|ลายเซ็นต์|ผลลัพท์|สังเกตุ|โน๊ต|เว็ปไซต์|อาทิตย์ที่แล้ว์|ปรากฏการ์ณ" <path>
```

ที่ถูกคือ `กฎ` (ฎ ชฎา) · `อนุญาต` · `ลายเซ็น` · `ผลลัพธ์` · `สังเกต` · `โน้ต` · `เว็บไซต์` ·
`ปรากฏการณ์` · `อาทิตย์ที่แล้ว`

สองตัวท้ายเป็นตระกูลเดียวกันคือ **การันต์ผิดที่หรือเกินมา** `ปรากฏการ์ณ` วาง ์ ไว้บน ร แทนที่จะ
เป็น ณ · `อาทิตย์ที่แล้ว์` มี ์ เกินมาท้าย ว ทั้งที่คำนี้จบด้วย ว เปล่า ๆ — **ทั้งคู่เป็นการจับสตริง
ตรงตัว ไม่ได้ generalize** ใครพิมพ์ ์ เกินที่คำอื่นด่านนี้ไม่เห็น การจับ "์ เกิน" แบบทั่วไปต้องใช้
คนละ pattern และยังไม่มีคลังข้อมูลรองรับว่าคุ้มกับ FP ที่จะตามมา จึงยังไม่ทำ

⚠️ **`ฏ` ไม่ใช่ตัวอักษรผิด** `ปฏัก` `ปฏิบัติ` ใช้ ฏ ปฏัก ถูกต้อง ด่านจึงจับ `กฏ` (ก + ฏ)
ไม่ใช่ `ฏ` เปล่า — **แต่ anchor ด้วย ก + ฏ ยังไม่พอ** `ปรากฏ` สะกด ป-ร-า-ก-ฏ ซึ่งเป็น ก
ตามด้วย ฏ พอดี จึงเข้าเงื่อนไขทุกครั้งทั้งที่สะกดถูก ต้องมี lookbehind `(?<!ปรา)กฏ` มากันไว้
(`references/false-positives.md` ตารางท้ายไฟล์) และ `ปรากฏการ์ณ` ยังถูกจับได้ตามปกติเพราะมี
สาขาของตัวเองใน pattern

> ⚠️ บรรทัดนี้เคยเขียนว่า `ปรากฏ` เป็นคำที่ anchor ก + ฏ กันได้แล้ว ซึ่ง**ผิด** — เป็นคำเดียว
> ในสามคำที่มันกันไม่ได้ วัดจริง 2026-07-30: ด่านเดิมขึ้นแดง 5 บรรทัดในไฟล์กฎของ repo เอง
> เพราะ `ปรากฏ` ล้วน ๆ (postmortem ใน `false-positives.md`)

### TH-OR-06 — ทับศัพท์สม่ำเสมอในเอกสารเดียว

ไม่ตัดสินว่าสะกดแบบไหนถูก (ทั้ง `แพตเทิร์น` และ `แพทเทิร์น` มีคนใช้) แต่**สองแบบในเอกสารเดียว
อ่านเหมือนคนละคน** วิธีตรวจคือ grep คำทับศัพท์ที่ใช้บ่อยในงานนั้น แล้วดูว่าได้กี่รูป:

```sh
grep -oE "แพตเทิร์น|แพทเทิร์น" <path> | sort | uniq -c   # ควรได้บรรทัดเดียว
```

คู่ที่เจอบ่อย: `แพตเทิร์น`/`แพทเทิร์น` · `คอนเทนต์`/`คอนเท้นท์` · `ดีไซน์`/`ดีไซน์เนอร์` ·
`อีเมล`/`อีเมล์` · `กราฟ`/`กราฟฟิก`/`กราฟิก` — **ในงานที่มีศัพท์ของทีมอยู่แล้ว ให้ยึดตามที่ทีมใช้**
(false-positive ข้อ 8) ไม่ใช่ตามราชบัณฑิต

**ของจริงจากคลังข้อมูลที่เจ็ด** `วอลเปเปอร์` กับ `วอลล์เปเปอร์` ปนกันทั้ง repo ในขอบเขตที่ผู้ใช้เห็น
(`apps/app-ref` + `packages/ui`) นับได้ **268 : 41** ก่อนกวาด เจ้าของเคาะ `วอลล์เปเปอร์`
แล้วกวาดในคอมมิตเดียว **เหลือรูปเก่า 0 · รูปใหม่ 357 จุดใน 44 ไฟล์** สามบทเรียน:

1. **ตอนเสนอให้เลือกรูปเดียว ให้แนบจำนวนของทั้งสองรูปไปด้วย** เจ้าของตัดสินได้ทันทีโดยไม่ต้อง
   ไปเปิดไฟล์เอง คำถามที่ไม่มีตัวเลขคือคำถามที่ต้องไปหาข้อมูลก่อนถึงจะตอบได้
2. **รูปที่ชนะไม่ใช่รูปที่เยอะกว่าเสมอไป** ที่นี่รูปข้างน้อย (41) ชนะเพราะตรงกับ flow ที่กำลังทำอยู่
   และถ้านับทั้ง repo รูปเก่ายิ่งนำขาด (709 : 94) — อย่าตั้งธงว่ารูปที่เยอะกว่าคือรูปที่ถูก
   และอย่ากวาดก่อนถาม
3. **"เหลือ 0" ต้องบอกว่า 0 ในขอบเขตไหน** รอบนั้นกวาดเฉพาะสตริงที่ผู้ใช้เห็น ส่วน `docs/`
   `poc/` และแอปอื่นยังเหลือรูปเก่าอยู่ 157 จุด ซึ่งถูกแล้วตามขอบเขต แต่ถ้ารายงานว่า
   "ทั้ง repo เหลือ 0" คือรายงานผิด

**TH-OR-03 เป็นกฎของตำแหน่ง ไม่ใช่กฎของตัวเลข** เงื่อนไขคือ **มีอักษรไทยขนาบสองข้าง**
เลขที่มีอักขระอื่นตามหลัง (`เส้น 1:` ตามด้วยทวิภาค · เลขท้ายบรรทัด · `v1.2`) grep ไม่แตะ
ในคลังข้อมูลกลุ่ม `เส้น <n>` มี 384 ครั้ง เท่ากันทั้งสองฝั่ง (384 → 384) และเทียบรายเรคคอร์ดแล้ว
ไม่มีเรคคอร์ดไหนขยับเลยสักตัว (1,670 จาก 1,670)

⚠️ **อย่าอ่านว่า "เลขใน label ปลอดภัยเสมอ"** — `ใบเซียมซีหมายเลข 9 นี้` ก็เป็น label
แต่มีไทยตามหลัง จึงเข้าเงื่อนไขและถูกแปลงจริง ตัวตัดสินคือสิ่งที่อยู่*หลัง*เลข ไม่ใช่ว่ามันเป็น label

**TH-OR-03 ใช้กับเนื้อความบรรยาย ไม่ใช่สตริง UI** สตริงอย่าง `วันนี้ครบ 8 ชม. แล้ว` (หมวด D

พังยังไง — `ในทาง`→`ด้าน` ทำให้ `คลี่คลายไปในทางที่ดีขึ้น` กลายเป็น `คลี่คลายไปด้านที่ดีขึ้น`
33 เรคคอร์ด · `ท่าน`→`คุณ` ทำให้ `เท่านั้น` กลายเป็น `เคุณั้น` 6 เรคคอร์ด · ตัด `อย่างยิ่ง`
ทำให้ `ความอดทนอย่างยิ่งยวด` กลายเป็น `ความอดทนยวด` 3 เรคคอร์ด — ทั้งหมด ship ขึ้น production
ไปแล้ว **ถ้าจะรันเป็นชุด ต้องมี gate ที่อ่านผลลัพธ์กลับ ไม่ใช่แค่นับจำนวนที่แทนสำเร็จ**
